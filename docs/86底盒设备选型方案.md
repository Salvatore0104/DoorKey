# 86 底盒门禁物联网设备选型方案

## 场景约束

| 项目 | 约束 |
|------|------|
| 安装位置 | 86 底盒（约 80×80×50mm，标准暗盒） |
| 供电 | 12V DC（门禁系统已有电源） |
| 有线网络 | RJ45 门禁专网（172.30.2.0/24） |
| 无线网络 | WiFi 连接家庭 HA 网络 |
| 功能需求 | 开门、视频、对讲 |
| 网络隔离 | 门禁网与家庭网不可二层桥接（安全要求） |

## 核心矛盾

门禁网与家庭 HA 网必须隔离，但设备需要同时访问两个网络：
- **门禁网侧**：接收门口机 UDP 46754 视频、UDP 46753 音频、发送 TCP 46752 控制命令
- **家庭网侧**：通过 WiFi 连接 HA，暴露 HTTP API 供 HA 调用

→ **必须使用双网卡设备**（有线接门禁网 + WiFi 接家庭网）

#### 网络配置

```bash
# /etc/dhcpcd.conf

# 门禁网卡 (usb0) - 静态IP，无网关，不转发
interface usb0
static ip_address=172.30.2.47/24
nogateway
nohook wpa_supplicant

# WiFi (wlan0) - DHCP 自动获取家庭网IP
interface wlan0
static routers=192.168.1.1
static domain_name_servers=192.168.1.1
```

```bash
# /etc/sysctl.conf — 禁用IP转发，确保网络隔离
net.ipv4.ip_forward=0

# 防火墙：门禁网卡不暴露任何服务
# iptables 规则
iptables -A INPUT -i usb0 -j DROP
iptables -A OUTPUT -o usb0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -o usb0 -p tcp --dport 46752 -j ACCEPT  # 仅允许主动连门口机
iptables -A OUTPUT -o usb0 -p udp --dport 46753 -j ACCEPT  # 上行音频
iptables -A OUTPUT -o usb0 -p udp --dport 46754 -j ACCEPT  # 视频请求(如需)
```

#### 软件部署

```bash
# 1. 系统准备
sudo apt update && sudo apt install -y python3-pip python3-venv git

# 2. 克隆项目
cd /opt
git clone https://github.com/Salvatore0104/DoorKey.git hr6107

# 3. 虚拟环境

# 4. 配置环境变量

export HR6107_WEB_PORT=8088
export HR6107_AUTH_REQUIRED=1

# 5. systemd 服务
cat > /etc/systemd/system/hr6107.service << 'EOF'
[Unit]
Description=HR-6107 Door Intercom Proxy
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/hr6107
Environment=HR6107_DEVICE_IP=172.30.2.47
Environment=HR6107_DOOR_IP=172.30.2.36
Environment=HR6107_WEB_HOST=0.0.0.0
Environment=HR6107_WEB_PORT=8088
Environment=HR6107_AUTH_REQUIRED=1
ExecStart=/opt/hr6107/.venv/bin/python run_hr6107.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable hr6107
sudo systemctl start hr6107
```

#### 功能实现

| 功能 | 实现方式 |
|------|----------|
| **视频** | 门禁网卡接收 UDP 46754 H.264，通过 WebRTC 转发给 HA/浏览器 |
| **对讲(下行)** | 门禁网卡接收 UDP 46753 G.711，解码后通过 WebRTC 播放 |
| **对讲(上行)** | 浏览器/HA 麦克风 → WebRTC → 重采样8kHz PCMU → UDP 46753 发门口机 |
| **开门** | TCP 46752 发送 `0003fe` 命令（通话中有效） |
| **来电通知** | TCP 46752 监听呼叫 → WebSocket 推送 → HA 传感器 |
| **继电器开门(备用)** | GPIO 17 触发继电器，并联门禁开门线（独立于网络协议） |

#### 优势与限制

**优势**：
- 直接复用现有 Python 协议代理代码，零移植成本
- 完整的 WebRTC 视频+双向对讲能力
- Linux 环境灵活，可加装 go2rtc/MediaMTX 做 RTSP 转发
- systemd 管理进程，稳定可靠

**限制**：
- 86 底盒空间紧张，USB Hub+网卡+声卡+降压模块堆叠较密
- 树莓派 Zero 2 W 仅 512MB RAM，H.264 解码+WebRTC 可能偏高负载
- USB 百兆网卡性能有限，但门禁视频仅 352×240@25fps 足够
- 需要焊接降压模块和继电器接线

#### 功能实现与限制

| 功能 | 实现方式 | 可行性 |
|------|----------|--------|
| **开门** | TCP 46752 发命令 / GPIO 继电器 | ✅ 完全可行 |
| **来电监听** | TCP 46752 服务端 | ✅ ESPHome custom component |
| **视频** | OV2640 采集 → WiFi MJPEG 推流 | ⚠️ 非门禁协议，自建摄像头 |
| **门禁视频接收** | UDP 46754 H.264 解析 | ❌ ESP32 难以解析私有H.264分片 |
| **对讲** | I2S 麦克风/扬声器 | ⚠️ 需自行实现 G.711 编解码 |
| **HA集成** | ESPHome 原生集成 | ✅ 最佳 |

**适用场景**：如果只需要"开门按钮 + 来电通知 + 自建摄像头"，ESP32 方案更轻量。
**不适用场景**：如果需要接收门口机的 H.264 视频并转发，ESP32 算力不足。

## 推荐方案

### 首选：方案 A（树莓派 Zero 2 W + USB 以太网卡）

**理由**：
1. **完整功能**：视频、双向对讲、开门、来电通知全部支持
2. **零移植成本**：直接复用现有 `hr6107/` Python 代码
3. **可扩展性**：后续可加装 go2rtc 做 RTSP、MQTT 桥接等
4. **社区支持**：树莓派生态完善，问题排查容易

### 备选：方案 C（GL.iNet MT300N-V2）

**适用场景**：如果 86 底盒空间极度紧张，或优先考虑网络隔离的可靠性。

### 不推荐：方案 B（ESP32-S3）

**理由**：ESP32 无法解析门禁私有 H.264 视频流，只能做"开门控制器"，功能不完整。

## 安装步骤（方案 A）

### 1. 硬件组装

```
步骤1: 焊接降压模块
  门禁12V+ → 降压模块IN+ → 降压模块OUT+ → Pi 5V
  门禁12V- → 降压模块IN- → 降压模块OUT- → Pi GND
  (用万用表确认输出5.0V±0.2V后再接Pi)

步骤2: 连接USB设备
  Pi USB口 → USB Hub → USB以太网卡 + USB声卡
  USB以太网卡 RJ45 → 门禁网线

步骤3: 连接音频
  USB声卡 MIC IN → 驻极体麦克风(注意极性)
  USB声卡 SPK OUT → 小喇叭

步骤4: (可选)继电器接线
  Pi GPIO 17 → 继电器 IN
  继电器 COM → 门禁开门线一端
  继电器 NO  → 门禁开门线另一端
  (与实体开门键并联，实体键仍可用)

步骤5: 装入86底盒
  注意绝缘：所有裸露焊点用热缩管包裹
  固定：用双面胶或尼龙柱固定各模块
  散热：树莓派Zero2W负载时约45°C，底盒内需留通气缝
```

## 安全注意事项

1. **断电施工**：接线前必须断开门禁12V电源
2. **电压确认**：接树莓派前用万用表确认降压模块输出为 5.0V±0.2V
3. **极性确认**：门禁12V电源正负极需用万用表确认，反接会烧毁设备
4. **绝缘处理**：底盒内所有裸露焊点用热缩管或绝缘胶带包裹
5. **散热**：树莓派 Zero 2 W 满载约 45°C，底盒盖板建议留通气孔
6. **网络隔离验证**：部署后从门禁网侧扫描树莓派，确认仅门禁协议端口可达
7. **不破坏原有门禁**：继电器并联接入开门线，不剪断原有线路，实体开门键仍可正常使用
